# Commonwealth Online 1.1.0

Commonwealth Online 1.1.0 is the combined release for the work previously grouped under 1.0.6 and the later 1.1.0 changes. It brings the public multiplayer foundation, server browser, character onboarding, save/reconnect work, player/world synchronization, hardened networking, Iroh internet hosting, the graphical host window, controller overhaul, host moderation, and release packaging together as one update.

## UI and server browser

- Reworked the Multiplayer server browser.
- Added public Browse listings, LAN discovery, favourites, recent servers, and Direct Connect.
- Added TCP/LAN and Iroh invite-code Direct Connect.
- Added strict EndpointId validation for Iroh joins.
- Added password prompts and retry handling for protected Iroh hosts.
- Improved server details, connection status, ping display, and recent-server information.
- Added join progress feedback, Cancel Join, and Retry Join.
- Fixed stale refresh results after closing and reopening Multiplayer.
- Fixed failed refreshes leaving Browse stuck loading.
- Fixed duplicate Direct Connect actions.
- Fixed shortcuts activating while typing.
- Escape can dismiss the server browser again.
- Fixed stale Direct Connect focus highlights.

## Controller and input overhaul

- Replaced the duplicate XInput controller path with PrismaUI V12 controller ownership.
- Controller ownership now follows the actual PrismaUI browser lifecycle and focus state.
- Cursor ownership and gamepad polling are gated on Fallout being the foreground application.
- Removed legacy input replay paths that conflicted with mouse-mode focus.
- Added controller navigation across tabs, lists, filters, Direct Connect fields, connection type, and Connect.
- Added an on-screen keyboard so controller users can edit Direct Connect and filter text fields.
- Added controller access to the TCP/Iroh transport selector.
- D-pad navigation can enter and leave Direct Connect without trapping focus.
- Tab selection now previews before it commits.
- Selection indices are clamped to the list shown by the active tab.
- Controller prompts now match the action of the focused control.
- Added an optional controller trace path for debugging input routing.
- Fixed pointer-mode flicker and A-button routing regressions.

## Character creation and first join

- Added first-time server onboarding through COVault109.
- Added LooksMenu and SPECIAL tracking to the multiplayer join flow.
- Improved third-person character creation camera behavior, face-edit positioning, and zoom.
- Restored player position, camera state, and FOV after customization.
- Added fallback and timeout handling when character creation does not open correctly.
- Added cleanup when first-time onboarding fails.
- First-time joins now wait until the player reaches a stable gameplay area.
- Setup saves from COVault109 can no longer become permanent multiplayer saves.
- Fixed the intro/onboarding cell path so first join can leave the setup cell and complete.
- Preserved save-safety and stale-join protections while splitting the join flow into smaller modules.

## Joining, saves, and reconnecting

- Added server-specific character and save profiles.
- First-time joins remain pending until the multiplayer save is actually created.
- Improved reconnect handling.
- Improved missing-save and deleted-save recovery.
- Improved exit-save and rotating exit-save handling.
- Equivalent TCP addresses such as `localhost` and `127.0.0.1` can resolve to the same profile.
- Iroh profiles are keyed to the server EndpointId instead of the temporary local bridge port.
- COVault109 setup saves are rejected during profile binding.
- Added profile backups and recovery.
- Added safer profile writes with rollback on failure.
- Disconnecting during onboarding now cleans up correctly.
- Old join attempts cannot interfere with newer joins.
- Current joins can recover cleanly when the connection disappears during startup.
- Recent Iroh servers reconnect using their EndpointId.

## Internet hosting with Iroh

- Added Iroh as a first-class internet transport.
- Home hosts can run internet sessions without router port forwarding.
- Iroh hosting does not require a public IPv4 address.
- Individual hosts do not need a VPS.
- Added direct connectivity when possible with relay fallback when needed.
- Added persistent Iroh client and server identities.
- Hosts expose a stable EndpointId used as an invite code.
- Added `co-tunnel.exe` as the Commonwealth Online Iroh transport helper.
- Added startup, shutdown, cancellation, and stale-generation handling for the sidecar bridge.
- Added real-network proof coverage for the Iroh transport path.

## Private invites and Public Browse

- Iroh transport and Public Browse are separate choices.
- Private Iroh hosting works without a directory server.
- A host can copy an invite code / EndpointId and share it directly.
- Public Browse is optional discovery and does not carry gameplay traffic.
- Public Iroh entries advertise transport, EndpointId, password state, and no TCP gameplay port.
- Stale Iroh metadata is invalidated when the sidecar stops or restarts.
- Loopback-only Iroh hosts no longer appear as broken LAN/TCP servers.
- Public Iroh registration proves ownership of the advertised EndpointId with a challenge/signature flow.
- Existing TCP public-host validation remains intact.

## Passwords, bans, admission, and admin security

- Added bounded Iroh admission framing before gameplay traffic is accepted.
- Gameplay is gated behind admission.
- Added Argon2id password verification.
- Added a `hash-password` helper so plaintext passwords do not need to be passed on the command line.
- Password verifiers are stored as PHC data rather than plaintext.
- Added per-EndpointId admission throttling.
- Added persistent EndpointId bans.
- Ban persistence is transactional.
- Banned clients are rejected before the gameplay socket is opened.
- Added a loopback-only admin channel protected by a token.
- Admin actions use authenticated Iroh session identity rather than loopback addresses.
- Added bounded rejection messages for malformed or rejected admission attempts.

## Directory and discovery security

- Added authenticated EndpointId ownership for public Iroh listings.
- Added directory challenge generation and signature verification.
- Added a shared Iroh/TCP directory-entry validation matrix.
- Iroh listings cannot smuggle a TCP host or port through the public directory path.
- Public TCP listings continue to use the address observed by the directory.
- Servers cannot redirect players to arbitrary public hostnames through registration.
- Private and special-use TCP addresses are blocked from public Browse listings.
- Directory capacity, connection counts, and request rates are bounded.
- Invalid directory configuration fails safely.
- Directory metadata is produced from worker-safe snapshots rather than background access to Qt widgets.

## What 1.1.0 changes for players

A player can now:

1. Install Commonwealth Online with PrismaUI_F4 as a separate dependency.
2. Start the graphical host window.
3. Host over LAN/TCP or enable Iroh internet hosting.
4. Keep the world private and share an invite code, or opt into Public Browse.
5. Add a password if desired.
6. Let friends join through Browse, LAN discovery, TCP Direct Connect, or Iroh Direct Connect.
7. Reconnect to recent Iroh servers using the saved EndpointId.
8. Kick or ban players from the host window.

For private Iroh sessions, the host does not need gameplay port forwarding or a public IPv4 address.
