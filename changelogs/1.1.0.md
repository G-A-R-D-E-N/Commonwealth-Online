# Commonwealth Online 1.1.0

Version 1.1.0 turns hosting from a mostly traditional TCP/server-directory workflow into a practical home-hosting flow. A player can host from a home PC through Iroh, keep the server private and share an invite code, or opt into the public server list. The update also replaces the old controller/input path, adds a full end-user host window, hardens identity and admission security, and closes a large set of lifecycle, reconnect, browser, and packaging issues that were not all represented in the earlier public changelog.

## Internet hosting with Iroh

- Added Iroh as a first-class internet transport for Commonwealth Online.
- Home hosts can run internet sessions without router port forwarding.
- Iroh hosting does not require the host to have a public IPv4 address.
- Individual hosts do not need a VPS.
- Added direct connectivity when available with relay fallback when needed.
- Added persistent Iroh identities instead of generating a throwaway identity every run.
- Hosts expose a stable EndpointId that acts as the server invite code.
- Added a bundled `co-tunnel.exe` transport helper for Commonwealth Online client/server packages.
- Added real-network proof coverage for the Iroh bridge and relay path.
- Added explicit startup, shutdown, cancellation, and stale-generation handling for the sidecar bridge.

## Private invites and optional Public Browse

- Iroh transport and Public Browse are now independent choices.
- Private Iroh hosting works without any directory server configured.
- A private host can copy its invite code / EndpointId and send it directly to friends.
- Public Browse remains optional and is used for discovery rather than gameplay transport.
- Public Iroh entries advertise `transport=iroh`, `port=0`, EndpointId, and password metadata.
- Iroh directory entries are validated separately without weakening the existing TCP public-host validation.
- Stale Iroh directory metadata is invalidated when the sidecar stops or restarts.
- Loopback-only Iroh hosts no longer advertise themselves as broken LAN/TCP servers.
- Public directory registration now proves ownership of the advertised EndpointId with a challenge/signature flow.

## Direct Connect and reconnecting

- Added manual Iroh Direct Connect by EndpointId / invite code.
- Direct Connect now lets players switch between TCP/LAN and Internet via Iroh.
- Added strict 64-character hexadecimal EndpointId validation.
- Added password prompting and retry handling when a protected Iroh host rejects an unauthenticated join.
- Added recent-server reconnect support keyed by the Iroh EndpointId.
- Server-specific save/profile identity for Iroh servers is keyed to the server EndpointId instead of the temporary local bridge port.
- TCP Direct Connect behavior remains available and unchanged.
- TCP and Iroh form values are preserved while switching connection types.

## Graphical host window

- Shipped the end-user graphical Host a World window that was only planned in 1.0.6.
- Added World name, description, player limit, port, visibility, and internet-hosting controls.
- Added Private / Invite Only and Public server list visibility modes.
- Added an Invite code field with copy support.
- Added Start hosting / Stop hosting flow.
- Added Iroh connection path and EndpointId status.
- Added optional password protection.
- Added connected-player and ban tables.
- Added Kick Selected, Ban Selected, Unban Selected, and Refresh controls.
- Added clearer Commonwealth/Fallout-styled presentation and improved small-window layout.
- Removed misleading dark row highlighting and improved form spacing.
- Runtime transport/password controls lock while hosting so advertised metadata cannot drift away from the live sidecar.
- Admin controls remain available while the transport configuration is locked.
- Unexpected relay shutdown now performs full sidecar/directory cleanup before the GUI unlocks.
- Local relay status and public invite identity are presented separately.
- Host preferences persist without writing plaintext passwords to `server-config.json`.

## Passwords, bans, and admin security

- Added bounded admission framing before gameplay traffic is accepted.
- Gameplay is gated behind the Iroh admission handshake.
- Added Argon2id password verification before the gameplay socket is bridged.
- Added a `hash-password` helper so the host can convert a password into the stored verifier format without passing plaintext on the command line.
- Password verifiers are stored as PHC data instead of plaintext.
- Added per-EndpointId admission throttling.
- Added persistent EndpointId bans.
- Ban persistence is transactional to avoid corrupting the ban store.
- Banned clients are refused before the gameplay socket is opened.
- Added a loopback-only admin channel protected by a token.
- Admin actions operate on authenticated Iroh session identity rather than the local loopback bridge address.
- Added bounded rejection messages for malformed or rejected admission attempts.

## Server browser and controller overhaul

- Replaced the duplicate XInput controller stack with PrismaUI V12 controller ownership.
- Controller ownership now follows the actual PrismaUI browser lifecycle and focus state.
- Cursor ownership and gamepad polling are gated on Fallout being the foreground application.
- Removed legacy input replay paths that conflicted with mouse-mode focus.
- Added controller navigation across tabs, server lists, filters, Direct Connect fields, and Connect.
- Added controller access to the TCP/Iroh connection-type selector.
- Added an on-screen keyboard so controller users can edit every Direct Connect text field.
- D-pad navigation can enter and leave Direct Connect without trapping focus.
- Tab selection now previews before it commits.
- Selection indices are clamped to the list actually shown by the active tab.
- Controller prompts now match the action the focused control will perform.
- Added a gated controller trace module for diagnosing input routing without leaving diagnostics enabled by default.
- Fixed stale Direct Connect focus highlights.
- Escape can dismiss the server browser again.
- Fixed pointer-mode flicker and A-button routing problems.

## Browser and join lifecycle hardening

- Split the join flow out of the oversized session-launch implementation and added explicit generation fencing.
- Old join attempts can no longer complete over a newer join.
- Hardened Iroh join cancellation and sidecar shutdown.
- Join failures are dispatched through the correct game-thread task interface.
- Password-required failures can transition back into the password prompt instead of ending as a generic connection failure.
- Stale sidecar state and stale EndpointId metadata are rejected instead of being reused.
- Added dedicated browser event, controller input, password prompt, recent-server, and keyboard modules to reduce cross-feature state coupling.
- Added focused contract coverage for manual Iroh connects, directory joins, recent reconnects, cancellation, controller ownership, and menu input.

## First join and onboarding fixes since 1.0.6

- Fixed the intro/onboarding cell path so first join can actually leave the setup cell and complete.
- Kept the existing COVault109 save-safety and profile-binding protections.
- Preserved the existing timeout, cleanup, and stale-join protections while the session-launch code was split into smaller focused modules.

## Directory identity and validation

- Added directory challenge generation and ownership verification.
- Public Iroh listings must prove control of the advertised EndpointId.
- Added a shared Iroh/TCP directory-entry validation matrix.
- Iroh listings cannot smuggle a TCP host/port through the public listing path.
- Existing TCP host restrictions remain intact.
- Directory/server metadata is refreshed from a worker-safe snapshot rather than reading Qt widget state from a background registration thread.

## Build, packaging, and release work

- Added dedicated Windows CI for the Rust `co-tunnel` transport.
- Added pinned Rust toolchain handling and short-path Windows build support.
- Added release checks for the Iroh sidecar and client/server package contents.
- Commonwealth Online does **not** redistribute PrismaUI_F4. PrismaUI remains a separate dependency.
- The client package carries Commonwealth Online's own PrismaUI views and `co-tunnel.exe`, while the PrismaUI framework/runtime is installed separately.
- Expanded deterministic C++ coverage for Iroh sidecar behavior, join generations, directory validation, browser refresh state, save-profile logic, packet limits, and profile storage.
- Expanded Python and browser regression coverage around Iroh hosting, LAN discovery, controller navigation, Direct Connect, password flow, and host runtime state.

## What 1.1.0 changes for players

The biggest difference is hosting. A player can now:

1. Start the graphical Commonwealth Online host.
2. Enable internet hosting through Iroh.
3. Keep the world private and share an invite code, or opt into Public Browse.
4. Add a password if desired.
5. Let friends connect through the server browser or manual Iroh Direct Connect.
6. Kick or ban players from the host window.

For private Iroh sessions, no gameplay port forwarding or public IPv4 address is required.
